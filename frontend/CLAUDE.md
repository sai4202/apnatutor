# ApnaTutor frontend

Next.js app for the ApnaTutor tutor marketplace. **Self-contained** — everything this project needs is inside `frontend/`. It talks to the backend only over HTTP, never through the filesystem.

Product rules live in `../docs/SOURCE_OF_TRUTH.md` (canonical), task status in `../docs/TASKS.md`.

## Commands

All from `frontend/`.

```powershell
npm run dev      # UI on :3000
npm run build    # production build, also type-checks
npm run start    # serve the production build
npm run lint
```

The backend must be running on :8080 for pages to load data. Start it with `cd ..\backend; .\mvnw.cmd spring-boot:run`.

## Next.js 16

**Read the guides in `node_modules/next/dist/docs/` before writing code.** Next 16 has breaking changes relative to most training data, and remembered App Router conventions are frequently wrong here. See the generated `AGENTS.md` note above.

`AGENTS.md` and this file's `@AGENTS.md` import line are regenerated by `next dev`. Leave them committed; deleting only recreates an uncommitted change.

## Environment

- Config comes from `.env.local` in this directory, loaded by Next automatically — no custom loader, no parent-directory reach. Add any new variable to `.env.example` in the same commit.
- `NEXT_PUBLIC_*` is compiled into the browser bundle and is therefore public. **Never put a secret behind that prefix.**
- Read the API base URL from `src/lib/api.ts`, never from `process.env` directly, so it stays changeable in one place.

## Conventions

- **TypeScript strict.** No `any` without a comment justifying it.
- **Server Components by default.** Reach for `"use client"` only when interactivity genuinely requires it — public pages must render fully server-side.
- **SEO pages must work with JavaScript disabled.** Programmatic city×subject pages are the primary acquisition channel; an empty shell defeats the whole strategy.
- **Branch on `ErrorCode`, never on error message text.** Messages get reworded; codes are contract.
- **Filter and search state belongs in the URL**, so results are shareable and the back button behaves.
- **Mobile-first.** Assume a mid-range Android phone on a slow connection is the typical visitor.
- Every list needs empty, loading and error states — not just the happy path.

## Never render an unmasked contact

Tutor and student contact details are the product: they are paid for. The API masks them, but the UI must never reconstruct, cache, log or display a phone number outside an explicitly unlocked lead. Treat any leak as a P0.
